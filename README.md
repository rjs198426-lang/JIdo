# J★Do — 나와 동행자의 자유여행

본인 또는 동행자와 자유여행을 계획하고 현장에서 확인하는 **개인용 Android 여행 앱**입니다. 공개 커뮤니티·판매·서버 동기화 없이 기기에 기록합니다. React 화면을 Capacitor 네이티브 앱으로 패키징합니다. PC와 모바일 브라우저에서도 동일한 화면을 개발·테스트할 수 있습니다.

[정식 앱 J★Do 1.29 설치 APK와 자료 이전 안내](ANDROID-DOWNLOAD.md). 1.26에서 업데이트하며, 구형 1.25는 전체 ZIP으로 자료를 옮긴 뒤 제거할 수 있습니다.

## 개인과 동행자 사용

첫 화면은 내 여행과 후보 장소이며, 새 여행은 인원 1명·원하는 도시 직접 입력·빈 일정으로 시작합니다. 기존 여행 기록은 그대로 읽습니다. 가이드 장소는 필요할 때 선택하며 추천 일정을 자동으로 넣지 않습니다.

`여행 중` 탭은 기기 날짜에 맞는 여행일을 열고, 다음 장소의 길찾기·방문 완료·건너뛰기·지출을 연결합니다. 방문 순서는 사용자가 정한 순서를 유지합니다. 해당 날짜의 숙소와 예약 첨부, 여행 연락처를 같은 화면에서 열고 다른 날짜도 선택할 수 있습니다. 숙소 이용 종료일은 체크아웃 날짜로 처리합니다. 지도 길찾기는 사용자가 누르면 Google Maps로 연결됩니다. 자동 교통 시간·시차 추정은 하지 않습니다.

동행자가 있으면 준비물 담당자를 지정하고 사람별·공용으로 볼 수 있습니다. 준비 목록 템플릿도 선택한 담당자에게 추가하며 같은 담당자에게 중복 추가하지 않습니다. 혼자 여행에서는 정산과 비용 분담을 숨깁니다. 여행마다 마지막 날짜와 작업 화면을 기기에 기억합니다.

`동행자에게 일정 전달`에서 하루/전체 일정 텍스트를 Android 공유 화면으로 보내거나 복사합니다. `앱용 일정 파일 전달`은 전체 여행의 독립 JSON 사본을 전하며 상대는 `여행 백업·공유 → 백업 파일 선택`으로 가져옵니다. 경비·예약 번호·연락처·첨부 파일은 제외하고 숙소명·주소·이용일은 포함합니다. 장소 메모는 선택할 때만 포함합니다. 전송은 사용자가 공유 대상에서 마치며, 사본끼리 자동 동기화되지 않습니다. Android 공유 화면의 실기기 검증은 별도로 필요합니다.

## 구현된 기능

- 21개 여행지의 숙소·이동·예약·날씨 가이드와 지역별 42개 코스. 선택한 코스를 날짜에 중복 없이 담습니다 ([구성과 조사 근거](PRACTICAL_GUIDES.md)).

- 가이드의 「블로그 후기」 탭에서 여행지별 2편, 총 42편의 네이버·티스토리 원문을 엽니다. 작성 연도·주제로 골라 보고 후기를 더 검색할 수 있습니다 ([선정 기준과 확인 범위](GUIDE_BLOGS.md)).

- 제목·로고·메뉴·본문·입력을 SUIT Variable 한 계열로 통일하고 굵기로 구분합니다. 글꼴을 APK에 내장합니다 ([출처·이용조건](ASSETS.md)).

- 21개 여행권·887곳. 기존 15개 여행지는 출처를 확인한 장소 각 50곳 이상, 추가 4개 여행권은 공개 보관본 기반 각 20곳, 괌·사이판은 미검증 편집 가이드 각 20곳입니다. 개인 블로그 후기와 여행자 가이드를 구분합니다 ([자료·선별 기준](PLACE_REVIEWS.md)). 장소 사진은 52곳, 사이판 대표 사진 1장을 내장하며 전체 사진 보강은 미완료입니다 ([사진 출처·검증 범위](ASSETS.md)).
- 장소마다 다른 실제 사진과 출처·이용 조건, 개인 사진 추가와 대표 사진 선택
- 도시·나라·장소 검색, 지역 및 관광/맛집/카페 필터

- 여러 도시를 한 여행에 추가하고 날짜별 체류 도시 지정

- 여행 준비 대시보드, 담당자·기한·분류·메모와 여행 유형별 준비 목록

- 방문 완료·건너뛰기·체류 시간 겹침 확인, 일정에서 바로 지출 기록

- 여행 전체 백업·복원 및 일정 텍스트 공유

## 개발 실행

Node.js **24 이상**, npm이 필요합니다.

```bash
cd /workspace/JIdo
npm ci --cache /workspace/.cache/npm
npm run dev -- --port 5173 --strictPort
```

기기 내 여행 관리에는 서버가 필요하지 않습니다. 기본 무료 장소 검색에는 API 키가 필요하지 않습니다. Google 검색을 선택할 때만 Google Maps Platform API 키를 빌드 환경에 등록해야 합니다. 별도 가이드 관리 서버 코드는 보존했으며 [GUIDES.md](GUIDES.md)를 참고하세요. 설치형 앱은 가이드 서버 연결·요청·자동 갱신을 사용하지 않습니다.

```bash
npm run build            # TypeScript 검사 + 배포용 화면 빌드
npm run native:sync      # 화면 빌드 + Android에 최신 화면 복사
npm run android:open     # Android Studio에서 열기
```

화면을 수정한 뒤에는 `native:sync`를 실행해야 네이티브 앱에 반영됩니다. 앱은 `dist/`의 파일을 포함하므로 개발 서버에 연결하지 않아도 실행됩니다.

## Android 설치용 APK

Java **21**, Android SDK **API 36**, Build Tools **35.0.0 / 36.0.0**을 사용합니다. 최소 Android 버전은 **7.0 / API 24**입니다.

클라우드에서 도구를 준비하고 서명된 설치용 APK를 만드는 명령:

```bash
cd /workspace/JIdo
python3 scripts/setup-java.py
python3 scripts/setup-android.py
npm run android:build
```

도구는 `/workspace/.cache/android-sdk`에 설치하고 Google 공식 메타데이터의 체크섬으로 다운로드를 검증합니다. Gradle 배포도 공식 SHA-256으로 검증합니다. 기존 HTTPS 프록시가 있으면 Gradle의 지원되는 프록시 설정을 이용합니다.

먼저 비공개 서명 백업을 `/workspace/.jido-signing`에 복원해야 합니다. 다른 위치는 `JIDO_SIGNING_PROPERTIES`로 지정합니다. 키가 없으면 빌드는 중단하며 키를 자동 생성하지 않습니다. 공개 인증서 지문은 `android/signing-certificate.sha256`에 고정했습니다.

결과는 `artifacts/jido-release.apk`와 `artifacts/JDo-android.apk`입니다. Android 기기로 파일을 옮겨 설치하거나 연결한 기기에 다음 명령을 사용할 수 있습니다.

```bash
/workspace/.cache/android-sdk/platform-tools/adb install -r artifacts/jido-release.apk
```

다른 개발 머신에서는 Android Studio에서 SDK 36을 설치하고 `ANDROID_HOME`, `ANDROID_USER_HOME`, `GRADLE_USER_HOME`을 자신의 쓰기 가능한 경로로 지정하세요. `npm run android:open`으로 연 프로젝트도 직접 빌드할 수 있습니다. 서명 백업을 복원한 뒤 `signing.properties`의 `storeFile`을 실제 비공개 키 경로로 맞추세요. 백업에는 개인 키와 비밀번호가 함께 있으므로 공개 저장소에 넣지 않습니다. Play Store 배포는 별도의 스토어 설정·AAB 검증이 필요합니다.

1.26부터 새 키와 `com.jido.travel.next`를 사용하며, 1.27부터 표시 이름은 원래 이름인 **J★Do**입니다. 1.26은 그대로 업데이트됩니다. 구형 `com.jido.travel`은 서명이 달라 직접 덮어쓰지 않습니다. 이전 앱에서 **내 여행 → 여행 백업·공유 → 전체 백업 저장**으로 ZIP을 저장하고 새 앱의 **전체 백업 불러오기**로 가져오세요. 사진·예약 파일은 전체 ZIP에 포함되며 일정 JSON에는 파일 바이너리가 포함되지 않습니다. 복원을 확인하기 전 구형 앱은 유지하고, 자료 확인 후 구형 앱을 제거하면 현재 앱으로 대체할 수 있습니다.

## 장소 사진과 화면 여백

일정 카드·여행 중 화면의 `장소 사진`에서 사진을 직접 추가하고 대표 사진을 선택합니다. 이름·위치는 무료 OpenStreetMap 검색 결과를 기본으로 선택합니다. Google을 선택할 때만 [GOOGLE_PLACES.md](GOOGLE_PLACES.md)의 키·결제 설정이 필요합니다.

하단 바의 실제 높이를 측정해 마지막 입력·버튼이 가리지 않도록 본문 여백과 스크롤 여백을 확보합니다. 일반 사용 설명 문구를 줄이고, 오류·저장 실패·백업에서 파일 제외 등 필요한 상태만 유지합니다.

## 여행 자료 첨부

자료 탭, 예약 확인서, 경비 영수증에 PDF·사진·문서를 직접 첨부할 수 있습니다. Android 파일 선택기로 고른 파일은 앱의 비공개 저장소에 복사하므로 원본을 옮겨도 여행에서 열 수 있습니다. 서버 업로드는 없습니다.

한 파일은 최대 25MB, 한 번에 10개, 여행당 300개입니다. PDF는 앱 안에서 페이지 이동·확대하고, 사진과 텍스트는 미리 봅니다. Office·HWP·HWPX·ZIP은 기기에 설치된 해당 파일 앱으로 엽니다. 지원 형식은 PDF, JPEG/PNG/WebP/GIF/HEIC/HEIF, TXT/MD/CSV, DOC/DOCX/XLS/XLSX/PPT/PPTX, HWP/HWPX, ZIP입니다.

첨부 파일은 일정 JSON 백업에 포함되지 않습니다. 앱 삭제·데이터 초기화 시 첨부도 삭제되므로 중요한 원본은 별도로 보관하세요. 브라우저 개발 환경에서는 IndexedDB에 파일을 저장합니다. Android 파일 선택기·PDF 화면의 실제 기기 검증은 별도로 필요합니다.

```bash
npm run build
npx playwright install chromium
npm test
```

시스템 Chromium을 제공하는 이 클라우드에서는 다운로드 없이 다음 명령으로 테스트합니다.

```bash
CHROMIUM_PATH=/usr/bin/chromium npm test
```

Playwright는 배포용 빌드의 프리뷰 서버를 실행하고 PC와 Pixel 7 크기에서 여행 편집·지도 연결·오프라인 저장을 검사합니다. 검색·필터, 저장 후 재시작, 일정 편집·순서 변경·삭제, 날짜 유효성, 상세 화면에서 일정 추가, 삭제 확인, 손상된 저장 데이터 복구, 320px 화면의 가로 넘침, Android 시스템 바 여백과 모달 키보드 포커스를 포함합니다. 네이티브 실기기 검증은 별도로 필요합니다.

## 데이터와 현재 범위

`src/data.ts`의 기본 데이터와 이미 기기에 보관한 가이드 캐시를 사용합니다. 설치형 앱은 서버에서 자동으로 가이드를 받지 않습니다. 사용자의 저장 목록·일정·메모는 현재 기기에만 보관되고 다른 기기와 동기화되지 않습니다. 앱 삭제나 데이터 초기화 시 사라질 수 있습니다.

이 버전에는 여행자 회원가입, 실제 예약·결제, 실시간 리뷰·가격·날씨, 도로 경로 계산 및 경로 최적화가 포함되어 있지 않습니다. 일본 도시 안내는 2026-10-14에 확인한 JNTO 자료를 바탕으로 작성했습니다. 운영 시간과 비용은 방문 전 공식 안내를 확인해야 합니다. 장소별 사진은 촬영자·이용 조건·출처를 연결하며 개인 사진으로 바꿀 수 있습니다.

앱 식별자는 `com.jido.travel.next`입니다. Java namespace는 기존 `com.jido.travel`을 유지하지만 설치 식별자·파일 공유 provider는 새 식별자를 사용합니다. 실제 스토어 배포 전에는 스토어 설정, 개인정보처리방침 및 데이터 출처를 준비해야 합니다.
