# 누락 사진 조사 — 2026-10-17

현재 Android 1.35의 내장 목록은 여행지 21개·장소 900개다. 파일 서명·내장 경로·출처 연결을 검사한 결과 여행지 대표 사진은 21/21개, 장소 사진은 65/900개다. 사진 없는 장소는 835곳이다. 사용자의 개인 사진과 첨부 자료는 검사하거나 수정하지 않았다.

- `coverage.json`: `node --experimental-strip-types scripts/audit-photo-coverage.mjs --output research/photos/coverage.json`으로 재생성하는 누락 목록.
- `missing-photos.csv`: 누락 장소의 고유 ID·한국어명·현지명·좌표. 이름이 비슷한 다른 지점이나 같은 도시의 풍경을 장소 사진으로 채우지 않는다.
- `network-proposal.json`: 새 사진의 이용 조건 조회에 필요한 네트워크 제안. 비밀 값이 없으며 설치·시작 스크립트와 저장소 구성을 변경하지 않는다. 이전 작업에 필요한 알려진 사용자 도메인도 보존했다. 이 파일 자체는 네트워크를 적용하지 않는다.

## 현재 접속과 차단

Wikimedia Commons ImageInfo API 요청은 세션 프록시에서 `CONNECT tunnel failed, response 403`으로 차단되었다. HTTP 원문 요청 전에 발생한 정책 거부다. 원본 이미지 호스트 `upload.wikimedia.org`의 기존 확인 파일 다운로드는 HTTP 200이었다. 사진을 받는 기능과 새 사진의 제작자·라이선스를 조회하는 기능의 접근 상태가 다르다.

설정 도구로 `commons.wikimedia.org`·`thumb.wikimedia.org` 추가를 시도했지만, 구성의 기준 버전이 변경되어 `base version is stale` 충돌이 났다. 저장은 확인되지 않았고 실행 환경에도 반영되지 않았다. 같은 저장 호출을 반복하거나 프록시·TLS 검증을 우회하지 않았다. 환경 설정에서 현재 허용 목록을 유지하면서 필요한 두 호스트를 추가해야 한다. 별도 설정 채팅이 필요하면 이 폴더를 다운로드해 새 환경의 최신 설정과 병합한다.

## 접속 복구 후 이어서 할 일

1. Commons API를 한 번 확인해 실제 HTTP 200과 ImageInfo 메타데이터 응답을 확인한다. 저장된 초안·게시만으로 접속 성공이라고 판단하지 않는다.
2. 누락 CSV의 장소별 현지명과 도시로 검색한다. 촬영 대상·주소/좌표·지점을 비교하고 무료 재사용 조건, 제작자, 원문 출처, 라이선스 링크를 확보한다. 검색 결과 첫 사진을 자동 적용하지 않는다.
3. 실제 사진을 열어 검토한 항목만 `src/photo-credits.ts`가 참조하는 사진 목록에 연결하고 `public/images`에 내장한다. 원본 파일의 SHA-256, 메타데이터 검토일, 변경 여부를 조사 기록에 남긴다. 출처는 기존 정보 화면에서 제공한다.
4. 적합한 사진을 찾지 못한 곳은 누락 상태로 남기고 남은 수를 정확히 보고한다. 타 장소 사진·AI 생성 사진·권한을 확인하지 않은 블로그 사진으로 대체하지 않는다.
5. 사진 파일 로드·장소 일치·개인 사진 우선순위·오프라인 표시·출처를 검사한다. 변경이 생긴 경우에만 Android 버전을 올려 동일 패키지·서명으로 APK를 배포한다.

이번 점검에서는 새 장소 사진을 적용하지 않았으므로 APK를 다시 배포하지 않았다. 기존 1.35 앱·사진·개인 기록은 그대로다.
