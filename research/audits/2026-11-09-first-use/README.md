# 처음 해외여행을 준비하는 사용자 관점의 평가 · 2026-11-09

평가 대상은 기존 사용 이력이 없는 사람이 J★Do를 설치해 여행지와 날짜를 정하고, 장소·예약·준비물을 모아 출발을 준비하는 흐름이다. 최신 main `65f466f`를 기준으로 빈 브라우저 저장소에서 재현했다. 실제 고객 인터뷰나 만족도 통계가 아닌, 합성 여행 자료를 사용한 과업 기반 전문가 점검이다. 개인 여행 자료는 읽지 않았다.

전체 판단: **첫 사용자가 앱의 역할, 준비 순서, 정보가 검증된 범위를 파악하기 위한 안내가 부족했다.** 기능은 각 탭에 있지만, 첫 여행을 만든 직후의 빈 화면이 다음 행동을 충분히 설명하지 않았다. 특히 날짜 입력 오류와 준비 완료로 오해할 수 있는 표현은 여행 준비에 영향을 주므로 우선 수정했다.

## 적용 방식

필수 온보딩·회원가입·추가 설정 화면을 만들지 않고 해당 일을 하는 화면에서 짧게 안내한다. 이미 작성한 일정·예약·경비·사진·개인 가이드·공공 장소 ID·90% UI 배율을 유지한다. 새 일정에는 시간을 자동으로 넣지 않고 예약도 명시적으로 연결할 때만 일정에 반영한다. 개인 자료를 외부 분석 도구나 GitHub로 보내지 않는다.

추가 가이드의 목록·본문은 기존의 고정 공개 GitHub 주소와 검증/저장 경로를 사용한다. 검색어를 외부 검색 API로 보내거나 입력 중 Google 유료 검색으로 전환하지 않는다. 가이드를 받는 버튼이 여행 생성 폼을 제출하지 않도록 버튼 타입도 분리했다.

## 검증 범위

- 빈 저장소에서 괌 여행 만들기 → 미래 출발일 변경 → 일정 확인 → 예약 기록 화면 → 준비물 기본 목록 → 오프라인/복구 흐름을 확인했다.
- 기존 파리 가이드의 성공/실패 응답 모형으로 생성 중 다운로드·날짜 보존·수동 도시 대체·초안 복원을 검사한다. 실제 공개 본문과 체크섬을 사용하되 네트워크 응답은 통제한다.
- 화면 크기320·393·1440px에서 홈·생성·빈 일정·준비물·오프라인 총15개 화면을 캡처하고 가로 넘침이 없음을 확인했다. 검토용 캡처는 합성 여행 자료다.
- 저장 실패·복구 원문·여러 여행 탐색·빈 시간·가이드 캐시·기존 기록 보존 회귀 검사를 배포용 정적 빌드에서 수행했다. 개발 서버 초기 변환 지연과 과거 날짜에 의존하던 테스트는 제품 문제와 구분하고 날짜 조건을 고정했다.
- 최종 테스트 수와 Android 배포·서명·공개 다운로드 확인은 `verification.json`과 저장소의 `ANDROID-DOWNLOAD.md`에 기록한다. 원문 변경 점검 자동화나 가이드북 수는 이번 UI 수정으로 변경하지 않는다.

## 남은 한계와 다음 평가 대상

1. Android 실기기의 한국어 키보드·큰 글꼴·제조사별 뒤로가기와 새 사용자의 실제 이해도는 브라우저 검사로 입증할 수 없다. 실기기 과업 테스트가 필요하다.
2. 여권·비자·입국 조건, 실제 영업·예약 확정은 이 앱이 자동 검증하지 않는다. 준비물 완료나 기록 충돌 없음은 출국 가능 판정이 아니다.
3. Google 지도/리뷰·Drive 실제 계정 인증과 해외 이동통신 품질은 응답 모형 검사와 구분한다. 이번 작업이 실제 Google 서버 또는 두 휴대폰 동기화 검증을 대체하지 않는다.
4. 첫 홈의 일본 도시 중심 탐색과 개인별 여행 추천 다양성은 후속 개선 후보다. 이번에는 첫 여행 생성 중 추가 도시를 찾는 경로를 개선했다.
5. 공통 앱 번들이 큰 빌드 경고가 남아 있다. 이번에는 데이터 구조·지도·동기화 모듈을 무리하게 나누지 않았으며 저사양 Android의 시작 시간 측정과 코드 분할은 별도 성능 과제로 남긴다.
